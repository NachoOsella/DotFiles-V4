# Behavioral parity

The old extension remains the production implementation. "Covered" means the listed native boundary has passing tests and code review. It does not mean complete CLI parity or exhaustive coverage of every legacy test. Legacy paths are relative to `extensions/subagents`; new test paths are relative to `extensions/subagents-durable/test`.

## Legacy test classification

- Domain path, communication and config tests describe policy to retain. The new tests do not import the old implementation.
- Coordinator, runtime and collaboration regressions describe observable behavior. The replacement tests use real Harness operations with deterministic provider or task gates.
- Persistence, fork usage and ownership assertions now exercise Durable boundaries, including actual SQLite process death.
- Cold loading, residency, run-sequence watermarks, copied usage, recovery graph snapshots and JSONL scanning assertions are obsolete. Their mechanisms were not ported.
- CLI rendering, Codemode nesting and exposure/structured-output contracts cannot be considered replaced while the required upstream APIs are absent.

## Intentional changes

- No loaded/unloaded lifecycle or maxLoadedAgents enforcement.
- Provider request capacity includes root. Tools and waits release that capacity. Logical agent capacity remains separate.
- Native suffix forks preserve structured history within retained turns instead of reconstructing text-only turns.
- Separate SQLite storage, with no migration of legacy identities or session files.
- The inspector is a native-host component, not a clone of every legacy screen or keyboard binding. CLI integration remains disabled.
- Native model lookup errors settle child work and produce a failure report. The tool API does not expose the host's model catalog for pre-admission validation.
- No MCP adapter is installed. A host that supplies foreign extensions must select its allowed capabilities explicitly; the package cannot identify arbitrary MCP-origin tools by unsupported namespace metadata.

## Release gate

Do not enable this extension as a CLI replacement yet. Durable must reach the CLI through a stable root/Harness integration. Recheck the assumptions and tests after any package upgrade. Resolve or explicitly accept the remaining tool contracts and UI integration gaps, then perform a separately authorized cutover. No cutover or legacy deletion is part of this work.
